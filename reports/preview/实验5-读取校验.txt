二、部署过程
2.1 部署方案与环境
本实验实际采用本地部署：先由 Vite 生成 dist/，再由 Node.js 原生 HTTP 服务提供静态页面和 JSON 资源。实验未部署到公网云服务器，没有安装独立数据库或业务中间件。用户数据保存在当前浏览器的 localStorage 中。

2.2 源代码与依赖检查
检查 package.json、package-lock.json、src/、public/ 和 server/ 目录。本次使用已安装的项目依赖，核对 Node.js 与 npm 版本；若在新电脑首次部署，可执行 npm ci 按锁文件安装依赖。本次没有重复执行依赖下载或操作系统安装。
命令5-1 环境与依赖检查命令
01  node -v
02  npm -v
03  # 首次安装时执行，本次复用已安装依赖：
04  npm ci
2.3 阅读资源准备与生产构建
执行 npm run build。该命令依次进行阅读数据准备、Vue/TypeScript 类型检查、Vite 前端打包和 Node.js 服务端编译。转换得到 238 篇文章和 20,261 条本地词典条目；该数量表示合并后的可查询词条，不表示全部为新编词汇。
命令5-2 构建流程（package.json）
01  npm run prepare:reading
02  npm run typecheck
03  vite build
04  tsc -p tsconfig.server.json
构建日志显示前端输出为 dist/index.html、dist/assets/ 等，服务端输出为 server-dist/index.js。Vue 与 TypeScript 检查通过，Vite 构建完成，日志保存在 reports/evidence/build.txt。
2.4 启动生产静态服务
本次验证脚本以 HOST=127.0.0.1、PORT=3208 启动 server-dist/index.js，避免占用项目默认端口。实际启动方式等价于以下命令；npm start 默认调用同一入口，未设置 PORT 时默认监听 3000 端口。
命令5-3 本地启动命令
01  HOST=127.0.0.1 PORT=3208 node server-dist/index.js
02  # 或使用项目脚本（默认端口 3000）：
03  npm start
浏览器访问 http://127.0.0.1:3208/。服务以 dist/ 为根目录，返回 HTML、JavaScript、CSS 和 JSON。访问不存在的路径返回 404，非 GET/HEAD 请求返回 405。本项目使用根路径资源地址，部署时应以 dist/ 为站点根目录。

2.6 数据保存与备份注意事项
localStorage 按协议、域名和端口隔离。例如开发服务器与 127.0.0.1:3208 不共享同一存储空间，换地址后看不到原记录不一定意味着文件丢失。测试使用临时浏览器配置，未操作日常浏览器中的学习数据。
需要迁移时应先使用应用的导出功能保存文件；旧版 IndexedDB 与旧备份未自动转换为新版记录，不应将两种格式直接混用。部署前应保留已有备份。本次未修改 Downloads 中原有备份文件。

表5-3 部署问题排查清单
问题
排查方法
页面无法访问
检查进程、HOST 和 PORT；确认端口未被占用。
构建失败
先查看 typecheck 输出和 Node.js 版本，再排查依赖安装情况。
资源返回 404
确认 dist/ 完整且作为站点根目录，检查资源路径与文件名。
看不到开发环境记录
检查协议、域名与端口是否变化；使用原地址或导出备份。
保存失败
检查浏览器存储权限与空间，先导出数据，避免清理未备份记录。
